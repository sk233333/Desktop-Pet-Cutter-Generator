## 遇到的问题

1. 推理模型把 `max_tokens` 全用在 `reasoning_content`，`content` 为空，
   视觉框请求误报「缺少 message.content」。
2. 视觉模型对「只保留兔子」「只要黑边」这类描述会只框头部或极小区域，
   SAM 随后给出 0.2% 的碎片掩膜，等于把主体切没。
3. 白边 / 贴纸外框无法用矩形框表达，模型和 GrabCut 都会把外白边带进来。
4. SAM 最初拿到的是「裁切后的整张图」而不是原始框，等于没有框提示。
5. `joy/sleepy` 注册 STATES 与新的零字节保护基线正面冲突。
6. W3 自动标注若落 manifest，需要 `eyes` / `mouth` 字段；schema 受保护，
   自动判真眼又被明确禁止。
7. W4 的 `angry/sad/shy` 不注册 STATES 时，挂到哪个基态没有既定口径；
   B-4 说话驱动嘴型还缺少分档 / 保持 / 衰减语义。
8. rembg 真实模型下载受环境网络限制，无法端到端验证；A 档真素材人眼
   未到，4 张质量评测只能登记「未标定」。

## 解决

1. 视觉请求 `max_tokens` 提到 4096、超时至少 90 秒；改用官方
   `thinking: {"type": "disabled"}` 后恢复到 2～3 秒。
2. 描述词只作提示，不再驱动分割；AI 模式改为手动框 + SAM/GrabCut；
   掩膜 <0.5% 自动整图重估，仍无效才回手动。
3. 新增「贴内层黑边」：暗色像素 → 闭运算补断口 → 最大闭合轮廓填充；
   兔子实测覆盖率 27.6%，外白边去掉。
4. 改为在**原图**上用原始框跑 SAM/GrabCut，再把掩膜裁回框内。
5. `expr_state.py` 恢复 `7531ff3` 字节；`joy/sleepy` 只做覆盖层键，
   `derive_allowed()` 仍七态；新增 `test_overlay_keys_do_not_rebuild_alias`。
6. W3 选 2：只读 `AnnotationReport`，不写 manifest、不改 schema；
   UI 只展示坐标，人工用现有补全器补标。
7. W4 停在语义红线，列出推荐映射与 B-4 待定项，等拍板后再做。
8. rembg 下载受限登记为环境限制，fake 端到端已验；A 档素材未到登记
   「未标定」，不阻塞其余轮次。

## 反思

- **AI 擅长切像素，不擅长定框**：把「框」交给人、「切」交给模型/本地算法，
  比让模型一次给出最终掩膜稳定得多。
- **默认关比事后补救重要**：文本引导、远程上传、AI 标注都默认关，勾选即
  同意上传；失败一律回手动，不让用户卡在 AI 上。
- **保护基线要写进测试**：`expr_state.py` 回零字节、7 项保护文件哈希、
  覆盖层键不进别名表，都是先有断言再谈功能。
- **文档必须跟着口径改**：③ 的 N/A 口径、70 节点匹配串、`save_cut_source`
  的新建期语义，都是回执里容易回潮的点，已写进
  `HANDOFF_V0_2.md` / `HANDOFF_AI_MOTION.md` §8。
- **该停就停**：W3 的 schema 红线、W4 的语义红线都没有硬闯；停线时给出
  证据和选项，比带活口进 v0.2 更省返工。
